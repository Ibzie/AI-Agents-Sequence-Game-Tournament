# AGENTS.md

## Project

Python benchmark for AI agents playing the board game "Sequence" versus each other. Two packages:
- `Game/sequence/` — pure-Python game engine (state, rules, board, deck, sequence detection, strategic analysis)
- `AI/` — LLM-backed agent with pluggable providers (Ollama, OpenAI, Anthropic)

Requires Python >=3.11.

## Commands

```bash
# Install (with dev deps for pytest)
pip install -e ".[dev]"

# Run AI vs CPU game (default: Ollama/llama3, localhost:11434)
python -m AI.run_game
python -m AI.run_game --provider openai --model gpt-4o
python -m AI.run_game --provider anthropic --model claude-sonnet-4-20250514
python -m AI.run_game --verbose   # debug logging

# Smoke test the game engine (random vs random, 100 games)
python Game/sequence/smoke_test.py   # must run from Game/sequence/ or fix imports

# Run tests (if/when added under tests/)
pytest
```

## Architecture

- `GameState` dataclass (`Game/sequence/state.py`) is the central state object, always passed immutably — `apply_move` deep-copies before mutating. Now includes `move_history` field recording all moves as `(player_id, move_dict)` tuples.
- Legal moves are generated by `Game/sequence/rules.py` and consumed as plain dicts with `type`, `card`, `position` keys.
- Strategic analysis (`Game/sequence/analysis.py`) computes near-sequences, completing positions, threats, forks, and move categorization. Used by the prompt builder to give the LLM strategic context.
- LLM agent (`AI/llm_agent.py`) sends enriched board state as text prompt, expects `{"move_index": <int>}` back (or `{"move_index": <int>, "position": [row, col]}` for wild jack placements), tries up to 3 times, falls back to random on failure. Default temperature is 0.3.
- Prompt builder (`AI/prompt.py`) renders the board with threat markers (! for your completions, X for opponent's), categorized move lists, near-sequence analysis, move history, and discard pile. Two-eyed jack moves are filtered to ~15 strategic targets instead of listing all ~80 empty positions.
- Provider abstraction (`AI/providers/base.py`) — add new providers by subclassing `BaseProvider` and registering in `AI/providers/__init__.py`.

## Gotchas

- `smoke_test.py` uses bare relative imports (`from state import ...`) — it only works when run from inside `Game/sequence/`.
- `run_game.py` manually inserts parent dir into `sys.path` for cross-package imports. Running as `python -m AI.run_game` (from repo root) avoids this.
- No formal test suite exists yet. `pytest` is declared as a dev dependency but no test directory or config is set up.
- No linter, formatter, or typechecker config. No CI.
- OpenAI/Anthropic providers require `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` env vars. Ollama requires a running Ollama server.
- Game is 2-player only. Win condition: 2 sequences (5-in-a-row including corners as wild).
- Deck has 2 copies of each standard card (104 cards). JH/JD are two-eyed wilds; JS/JC are one-eyed removal jacks.
- Two-eyed jacks generate a separate legal move for every empty non-corner position (~80 on an empty board). The prompt builder filters these to strategic targets only. The game engine still generates all positions for validation.
- `analysis.py` uses sliding-window detection for completing positions but a separate run-based method for partial sequences. Both treat corners as wild.
